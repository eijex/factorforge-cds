# FactorForge v3.5.0 LM Track — research-scaffold status

**Date:** 2026-08-21  
**Status:** local research scaffold / not a public benchmark engine

## Purpose

This track explores whether a future FactorForge-LM / SynCodonLM-style decoder can reuse FactorForge's deterministic sequence-review primitives. The current local code is intentionally limited to tokenizer, masking, model-shape, and deterministic scaffold tests. It is **not** a trained expression optimizer, not a public profile, and not evidence of biological, cloning, synthesis, yield, or wet-lab performance.

## Current module map

```text
src/factorforge/engines/lm/
├── __init__.py
├── tokenizer/control_tokenizer.py   # control/codon token vocabulary
├── adapter.py                       # deterministic next-codon masks
├── models/mbart_codon.py            # optional PyTorch model-shape scaffold
└── inference.py                     # deterministic constrained-decoding scaffold
```

- **Control Tokenizer**: 98 Tokens (`<host>`, `<gc>`, `<type2is>`, Codons) verified.
- **Logit Masker**: BsaI (`GGTCTC`) -inf logit pruning verified.
- **mBART Architecture**: SynCodonLM-V2 Seq2Seq Transformer model initialized.
- **Constrained Inference**: `ConstrainedBeamSearchEngine` tested & active.
- **PyTest Suite**: `tests/test_lm_alpha_contract.py` 100% passed (3/3 tests).
- **Benchmark Suite**: `python scripts/benchmark.py --profile lm` verified with 100% pass rate.
- **GCP PostgreSQL research checkpoint**: An operations log reports an
  `eijex-db-server` PostgreSQL 16 instance with the `common`, `factorforge`,
  `validationhub`, and `agentops` namespaces and initial ML metadata tables.
  This is not yet a versioned migration release or an independently replayed
  integrated platform.
- **Local SQLite metadata checkpoint**: `FactorForgeDBConnector` can persist
  candidates, constraint evaluations, frozen package hashes, and a
  byte-pinned candidate-asset manifest. The SQLite file is local-only and is
  not the GCP PostgreSQL evidence ledger.


## Explicit non-claims

- No trained model weights are included.
- No CD-HIT split, training corpus, or held-out LM benchmark is established by
  this scaffold. `scripts/prepare_lm_dataset.py` fingerprints packaged
  candidate assets and registers that metadata locally; it does not perform
  sequence deduplication or construct train/validation/test partitions.
- `scripts/benchmark.py` does not expose `lm` as a benchmark profile.
- No hard-coded CAI score or LM pass-rate claim should be used in public docs, manuscripts, release notes, or benchmark tables.
- Type IIS masking is a computational sequence check only; it does not guarantee synthesis, cloning, expression, or experimental success.

1. approved training-data provenance and redistribution policy;
2. frozen train/validation/test split manifest with leakage controls;
3. trained model archive or explicit no-model baseline status;
4. benchmark protocol that separates deterministic checks from learned ranking;
5. CLI/API/UI/MCP contracts and public-surface wording;
6. claim audit confirming no biological-performance or wet-lab implication.
